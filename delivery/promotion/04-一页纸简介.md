# SpecWave · 一页纸简介

> **给决策者看的 60 秒版本**——这是什么、护城河在哪、下一步去哪、风险与应对。

---

## 一句话

**SpecWave**（`spec-wave@2.1.3`）是「**跨宿主规范分发器**」——把 AI 编码的纪律从"提示词"升级为"机械门禁 + 留档可审计的过程轨"。**MIT 开源、零云、一条 `npx` 入门**。

---

## 解决的问题

| 痛点 | 现状 | SpecWave 的解 |
|------|------|---------|
| 规范散落、版本不一致 | 同一规范在 4 个文件里硬编码，门禁结论漂移 | 单一真值源 + 分层覆盖（spec-kit 范式） |
| 规范"不被执行" | `AGENTS.md` 是 prompt，不是 gate | 进程内机械门禁，**退出码 2 阻断管道** |
| 没有过程留档 | AI 做了什么没法复盘 | S2 过程域（tasks/reviews/invokes）**永不覆写** |
| 角色执行能力一锅炖 | AI 能干啥不能干啥没有边界 | **hat 帽制（starter 4 帽 + extended 4 帽，共 8 帽）** |

---

```

│                  SpecWave（spec-wave@2.1.3）                   │

│  ┌────────────────────┐      ┌────────────────────┐            │
│              │                       │                         │
│              └──────────┬────────────┘                         │
│                        ▼                                       │
│  ┌────────────────────────────────────────┐                    │
│  │ ICVO 内核                              │                    │
│  │ Inform · Constrain · Verify · Orchestrate│                  │
│  │ + hat：starter 4 + extended 4（共 8 帽）│                   │
│  ┌────────────────────────────────────────┐                    │
│                        ▼                                       │
│  ┌────────────────────────────────────────┐                    │
│  │ 落盘：.coding-kit/ + .dsh/skills/      │                    │
```

## 差异化（护城河）

五家 AI 编码规范标杆的能力覆盖矩阵：

| 能力 | Claude Code | Cursor | spec-kit | Ruler | Kiro | **SpecWave** |
|------|:-----------:|:------:|:--------:|:-----:|:----:|:-------:|
| 跨宿主规范注入 | — | — | 30+ 集成 | 32 个目标 | — | **2.0.0 已交付** |
| 规范**机械执行** | ✅ 退出码 2 | ✅ failClosed | 流程性 | — | ✅ 事件驱动 | ✅ **进程内机械判定** |
| 过程轨**留档** | — | — | ✅ spec/plan/tasks | — | ✅ req/design/tasks | ✅ **S2 永不覆写** |
| **角色分帽** | — | — | — | — | — | ✅ **starter 4 帽 + extended 4 帽（共 8 帽）** |
| 零云/离线可用 | — | — | ✅ | ✅ | — | ✅ |
| 旧产品线迁移治理 | — | partial | — | — | ✅ 完整范式 | 1.x 已落地 |

**关键判断**：五家标杆中**无任何一家**同时提供「**门禁 + 过程轨留档 + 角色分帽**」的等价物。这是 SpecWave 的护城河。

## 风险与应对

| 风险 | 应对 |
|------|------|
| R-01 `.cyning-harness` 双重语义（旧产品线痕迹 vs SpecWave 现行落盘） | 新落盘统一 `.coding-kit`/`.dsh/coding-kit`；旧目录仅 legacy 探测 + 只读降级 + `upgrade` 提示 |
| R-02 宿主单点依赖 | 2.0.0 引入宿主适配表（AGENTS.md 为默认落点 + 各宿主特化）；DSH 由"唯一宿主"转为"**四宿主之一**" |
| R-03 提词供应链风险（落盘资产被改 → 污染注入给模型） | 现状：注入结果标注 `source`（package/override）已落地；**assets sha256 清单 + `assets verify` 命令目前仅规划中，尚未实现，不宣称已有能力** |
| R-04 内部 X7/X6/X11 三项冲突（4 份硬编码、版本钉偏差、旧目录名双重语义） | F1 + F5 + F4 分别收敛；2.0 启动前已归零 |
| R-05 评测性能口径未锁定为 SLA | 4 次中间确认已闭环为"建议基线"（不构成对外 SLA）；README 显式标注 |
