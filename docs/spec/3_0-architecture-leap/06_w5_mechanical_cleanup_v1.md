## 5. 设计要点

- **NEW-6 通配**：黑名单匹配从「精确后缀相等」改为「扩展名语义通配」，覆盖 `.bak2` / `.bak.md` / 尾空格 `.bak ` 等变体；`files` 否定项同步防止打包面与卫生门分叉。
- **NEW-8 备份保护**：`pins fix` 清理自身生成的备份时，若同名 `.bak` 已存在（用户自有文件）→ 改名避让或跳过，**绝不无条件 `unlink`**。
- **R-6 口径（防与 failClosed 冲突）**：**skip 仅限「环境不具备」（git 不存在/不可执行）**；「钉面真偏差」一律 exit 2。两者在输出中**必须可区分**。

## 6. 方案对比（R2 摘要）

| 方案 | 结论 | 理由 |
|------|------|------|
| 卫生门 = 通配语义 | **采纳** | 变体形态（`.bak2`/尾空格）绕过精确后缀已实锤 |
| 卫生门 = 维持精确后缀逐个补 | 弃选 | 打地鼠 · 同型补丁教训（2.4 N12） |
| NEW-7 = 第二控制点 或 显式单点声明 | **二选一皆可（task 定稿）** | 核心是不允许「以为有双保险」的隐性单点 |
| R-6 = 环境不具备显式 skip + 分档诊断 | **采纳** | 2.4.1 验收真实教训（硬约束 10）· skip≠放行：真偏差仍 exit 2 |
| R-6 = git 不可用即 fail | 弃选 | 无归因红 = 不可诊断 · 违硬约束 10 |

## 7. 验收标准（必须自证，不接受「我改完了」）

1. **NEW-6 负向 fixture**：`.bak2` / `.bak.md` / 尾空格 `.bak ` 均被拦。
2. **NEW-8 负向 fixture**：用户既有同名 `.bak` 在 `pins fix` 后**存活**。
3. **NEW-12 fixture**：以路径为 key 的 JSON 输出被相对化（断言无绝对路径 key）。
4. **R-6**：在 git 不可用环境（模拟 license 未同意 → exit 69）下，套件**显式 skip 而非 fail**，且 `pins check` 输出区分「git 不可用」与「钉面偏差」（后者仍 exit 2）。
5. **R-1 回归确认**：跨目录 `host validate --json` 仍无绝对路径（以 2.4.2 行为为基线 · 只验不回改）。
6. `npm run typecheck` 0 错 · `npm test` 全绿（含新增）· `pins check` 17/17。
