## 2. P0 门禁纪律

1. 判定走**进程内机械逻辑**，exit 2 = failClosed 阻断档；本版新增/修严的判据（schema 校验 · 闸泛化 · W4 语义闸 · W6 闸接线）沿用同一语义。
2. **禁止**新增任何 `--force` / `--allow-*` 绕过参数（硬约束 2）。
3. 既有豁免旗标语义不变；修严波及存量时循 2.3.1 N11 / 2.4 D-24-W2-NO-RETRO 先例入 `docs/harness/legacy-gate-exempt.yaml` 留痕（四字段齐 · 显式类型判），**非静默放过**；**不追溯存量**（硬约束 7）。
4. **修严型变更必须配负向 fixture 回归锁**：凡「修复前真红、修复后转绿」的构造一律固化进测试套件（硬约束 6）。
5. **闸不落表即虚设**（硬约束 15）：人工闸只有写在 task 文 `### 人工闸` 节才可机检（`parseHumanGates` 只读该节）；规划档 / SPEC 的闸表属人工纪律，**不得据此宣称「闸已生效」**。新增闸 `blocks_hats` 须**显式含 `30`**，否则 W1 泛化判定不会咬。
6. **判据两类处置相反**（硬约束 11 · 2026-09-15 裁决）：**防伪类**（结论闸 / pins / 豁免真实性）继续语义化；**自评类**（KPI 等给思考打分的判据）不语义化，只保留存在性约束。
7. **环境依赖必须可诊断**（硬约束 10）：凡对外部二进制（git 等）有硬依赖的门禁，失败信息按因分档，套件在环境不具备时显式 skip（且输出中可与「真偏差 exit 2」区分）。

## 4. 对外文案纪律（事实卡黑名单 + 竞品口径修订前禁称）

- **未落地能力一律「将新增 / 规划中」口径**（硬约束 9）：A3 `hooks`/`verify` surface 在 W2 兑现前，对外**不得**声称「门禁可入宿主」；A3 能力可声称到什么程度由 W7 对外口径边界定稿（受事实卡黑名单约束）。
- **本体校验对外只声称「SHACL 语义子集」，不得声称 W3C 一致性**（硬约束 13 · 自研实现与标准实现可能行为分歧）。
- **竞品口径 K-1~K-4 修订前**（W7 台账），新增对外物料**不得**再引用过期数值（「30+ 集成」「105 扩展」「22 presets」）与「spec-kit 门控是流程性的」旧定性；差异化叙事落点已迁移为「门禁随包内置（零装配）+ 可多宿主物化」，不再落在「有没有机械门禁」。
- 事实卡黑名单过期表述（`dsh-coding-kit` 产品名 ·「四宿主」·「406 用例」等）不得回潮。
- **本体开放边界裁决落盘前**，对外文案不得暗示「消费者可自定义本体」（W3 ONTO-OPEN 待决）。

## 5. 版本路由纪律（硬约束 16 · 复裁已锤）

- **非 breaking 的工作一律不为它单开 minor**：补丁活儿走 patch，重构活儿随所在 major/minor 列车首波。**开新 minor 须先证「有消费者可观察的新增能力」**；仅「想要独立验收 / 回退粒度」不构成开 minor 理由（改用 M1 独立验收文 + commit 级可回退满足）。
- **W0 不迁 2.5.0**（D-30-VERSION-ROUTE · 复裁五条理由 + 翻案双触发器见 README 已定案表）。
- RELEASING.md 分工不变：①–⑦ 与 bump/tag 可 Agent，⑧ publish 仅人。

## 6. 流程边界（本棒与后续棒）

- 本棒（10-spec）只产出 SPEC 系列夹；**不改实现代码 `src/` `bin/` `assets/` `test/`**。
- **PLAN 明示「未复核代码行号现值」**：本系列引用的行号（`cli-host.ts:370-379` 等）均为起草轮快照，**各波 10-task 起草时必须回源码复核现值**，不得沿用。
- 后续每波独立链路：10-task → 20-task-audit（审查文落盘 reviews/）→ HG-AUDIT-R1 → 30/40（GATE_VERIFY 首输出 → 实现 → 自证 → `gate-check` → `task close --yes`）→ 独立提交 `feat(3.0-W<n>): …`（**禁 `git add -A`** · 每波提交前 `npm run typecheck` + `npm test` 必过 · 硬约束 8）。
- **波次特有硬前置**：
  - **W0**：独立验收文（M1）**必须早于 W1 动 schema**；重构与行为变更严格分离 commit（硬约束 5）。
  - **W1**：schema 变更评审文落盘 + `HG-SCHEMA-CHANGE` 人闸通过 → 才可改码（硬约束 3）；该闸**必须落 W1 task 的 `### 人工闸` 表**（硬约束 15）。
  - **W2**：W1 catalog 未就绪则 B5 顺延，**不得抢跑**。
  - **W3**：前置研究文落盘 `docs/harness/reviews/`（tracked · **不得只引 `.workbuddy/`** · 硬约束 14）后才可排实施。
  - **W4**：判据语义方案评审文落盘后才动手（循 D-24-W2-REVIEW-FIRST 先例）。
- **证据必须入库**（硬约束 14）：`.workbuddy/` 仅作起草工作区，**不得作为唯一证据面**；被引为证据的材料须镜像入 tracked 路径并回填仓内链接。
