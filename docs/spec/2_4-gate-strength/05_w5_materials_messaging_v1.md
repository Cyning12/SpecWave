## 5. 设计

### 5.1 物料处置二选一判据（task 定稿）

- **翻新**：该物料仍作为现行对外复用入口（如单页/一页纸）→ 更新到 2.3.x 事实面（数字以 bump 前实测为准 · 宿主 13 · 用例数如实）。
- **快照标注**：历史性叙事物料（如发布博客）→ 文首一行「历史版本快照（2.1.3 时点 · 现行事实面见仓根 README）」，正文不改写历史叙事。
- 判据默认：01/02/04 翻新或快照按维护者意图（task 阶段定 · 默认快照标注为最低代价合规）；03 发布博客天然历史快照。

### 5.2 口径收窄措辞（task 定稿 · 要点）

- T-03：「assets sha256 清单可**防意外漂移/防遗忘**；对主动投毒的防护依赖 npm provenance（当前**未启用** · 配置指引见 docs/guides/provenance_oidc_trusted_publishing_guide_v1_zh.md）」。
- 安全设计 A-1 行完整性依赖列追加限定：「assets sha256 清单（防漂移口径 · 防投毒依赖 provenance · 未启用）」；`:77`「篡改发现」收窄为「意外漂移发现」。

### 5.3 与 pins 钉面联动

W1 修严后 pin-16/17 覆盖 README 链接与宿主表——本波 README 改动**随改随跑全量 `pins check`**（00 §5）；aider 行改动不得破坏 pin-17 表行命中形态（表行内保留 host 词锚）。

## 7. 验收标准（必须自证，不接受「我改完了」）

1. **物料机检**：4 份逐份 grep 黑名单词（`四宿主|406 用例|2\.1\.3` 现行表述位）→ 命中为零 **或** 快照标注行存在；处置方式（翻新/快照）逐份留证。
2. **口径机检**：README / 事实卡 grep「可机检」（T-03 语境）→ 零命中或带降调限定；`delivery/安全设计.md` `:77` 与 §5.3.1 A-1 行含收窄/「未启用」标注。
3. **关账声称核查**：对外面「关账必经审查通过」出现处清单 + 口径与 W2 状态一致的结论留档。
4. **aider 行**：`README.md` 双语含 `conventions-file: AGENTS.md` 写法；`pins check` 全量 PASS（pin-17 表行命中不破）。
5. `npm test` 全绿（文档波 · 防测试夹中文案断言漂移）· `node bin/specgate.js pins check` exit 0。
