## 1. 背景

2.3-W4 把 reviews 闸从「审查文存在」升级为**结论级**（须含可机读通过词）；V2 发现 A2 绕过：审查文**只写「通过」二字、无结论节**即过闸（§3.L · 本轮唯一 P1）。2.3.1 已修 N11 本体：`evalReviewConclusion`（`src/cli-checks.ts:684-704`）**强制结论/签收节存在**（无结论节 → 直接判未通过 · 禁止回退全文 · :702；通过词 `REVIEW_PASS_RE` :681 须落结论节内），并补 A2 负向 fixture。

**残余（2.3.1 验收档主动登记 · 归 2.4）**：绕过面从「全文」收窄为「**结论节内**」——结论节存在但**只写「通过」二字**（无实质签收内容）仍可机读过闸。这是 §6 N11 建议原文即留的强度权衡，本波收口。

## 2. 目标

结论级闸的判据从「结论节存在 ∧ 通过词落节内」推进到「结论节含**最低限度实质签收内容**」——杜绝空结论节/单通行词过闸；**具体强度档位由评审文定夺**（本 SPEC 不定死档位），新行为**不追溯存量**（D-24-W2-NO-RETRO）。

## 5. 设计

### 5.1 现状机械口径（本棒只读复核）

- `REVIEW_SECTION_HEAD_RE = /^#{2,3}\s*(?:[一二三四五六七八九十]+[、.]\s*)?(结论|签收)/`（`src/cli-checks.ts:680`）——节标题以「结论/签收」起首的节合并。
- `REVIEW_PASS_RE = /(\bPASS\b|ACCEPT|签收|零内容阻塞|零阻塞|通过)/i`（:681）。
- 无结论/签收节 → 直接判未通过（:702 · 2.3.1 N11）；有节 → 通过词须落节内。
- **缺口**：节内内容为「通过」二字即同时满足「节存在」与「通过词落节内」。

### 5.2 候选强度档位（评审文定夺 · 本 SPEC 只列不选）

| 档 | 判据 | 代价/风险 |
|----|------|-----------|
| S1 | 结论节去通过词后须残留 ≥ N 字符实质内容 | 最简单 · 「N」取值主观 |
| S2 | 结论节须含结构化签收字段（如 `结论:` / `审查人:` / `日期:` 行） | 机检最稳 · 对存量与模板有约束 · 须同步 20-task-audit 帽条文模板 |
| S3 | 通过词须带上下文窗（前后 M 字符内非空白内容 ≥ K） | 折中 · 实现复杂度中 |

### 5.3 波及处置纪律

循 2.3.1 N11 先例：抽验样本核因 → 波及条目入 `legacy-gate-exempt.yaml` reviews 节（四字段齐 · `typeof === 'string'` 显式类型判 · reason 点名本波接线波及）→ 裸 `verify` 复跑 PASS（豁免命中留痕）。

## 6. 方案对比（R2 摘要）

| 方案 | 结论 | 理由 |

## 7. 验收标准（必须自证，不接受「我改完了」）

1. **评审文落盘**：`docs/harness/reviews/` 含强度方案评审文（候选档位对比 + 存量合规率实测 + 定档结论），且经 20-task-audit R1——**30 动手前硬核对**。
2. **负向 fixture 真红转绿**：「结论节存在但只写『通过』二字」→ 修复前 `verify --task` exit 0（复现残余形态）· 修复后 **exit 2**；合规审查文（含实质结论节）→ exit 0。
3. **负面词守卫不回退**：通过词 + 未否定「退回」仍 exit 2（2.3-W4 B2 对照形态回归）。
4. **存量波及登记**：波及清单 + 豁免条目落盘（四字段齐）· 裸 `verify` 复跑 PASS 且豁免命中留痕数与登记一致；零波及则登记「零波及」结论。
5. `npm run typecheck` 0 错 · `npm test` 全绿（含新增）· `discipline-coverage.yaml` 相关 note 回写（若覆盖表口径受影响）。
