## 2. 裁定总表（30 须遵守）

| # | 议题 | 裁定 |
|---|------|------|
| **C1** | 空解析告警输出通道 | **双通道、互不污染 stdout 主载荷**：① **人读 / 非 `--json`**：告警写 **stderr**（禁止打到 stdout）② **`--json`**：信封**只增**顶层字段 `warnings: string[]`（元素为可操作字符串）；**不得**把告警文本插入既有字段值或改写既有键语义 |
| **C2** | 与既有 `status` 模式关系 | 现行 `status` 部分告警仅 `console.error`、未入 JSON。本波 **`--json` 消费方须能机读** ⇒ **强制**入 `warnings`；允许**同时**镜像 stderr（便于人盯 TTY），但机读真值以 JSON `warnings` 为准 |
| **C3** | 文案要点（须可操作） | 须同时覆盖两独立失效通道：① **列数**：检测到 `### 人工闸` 但 0 行被识别 → 提示确认是否为 **4 列**（末列 `说明`）② **id 内嵌 `**`**：并列提示 id 单元格内勿内嵌粗体（外层整格包裹 `**HG-…**` 仍可解析）· 建议含「出现次数 / 0 行」类可诊断信息 · **避**术语机检变体词（如裸「门控」） |
| **C4** | 是否构成「契约变更」 | **是 · 轻度 · 可观测性 additive**（新增告警通道 / 可选 JSON 字段）；**不是** breaking：不改 exit、不改 `may_start_30`、不删/不改既有 JSON 键语义 |
| **C5** | 存量 `--json` 消费方影响 | **只增不改**：忽略未知字段的消费方零影响；读固定 schema 且拒未知键的消费方极少见——若存在，属其过严；本波**不**为此放宽解析或改判定。既有键（`may_start_30` / `blockers` / `gates` 等）**字节语义不变** |
| **C6** | `GATE_ROW_RE` | **不放宽** · 第 4 列仍必选 · 报告「改实现使第 4 格可选」**不采纳** |
| **C7** | `evaluateMayStart30` | **不改** · 阻断仍由其决定；空解析时既有 fail-closed（闸视为缺失 / pending 理由）**保留**；告警只补「表未被识别」可见性，**不替代**判定 |
| **C8** | exit code | **不变**：`check` 恒 0 等既有档位；告警**不**单独抬高/压低 exit |
