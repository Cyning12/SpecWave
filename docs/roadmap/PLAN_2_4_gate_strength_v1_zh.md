## W1 · pins 提取修正（本次核心）

- **范围**：N7 —— pin-16 链接提取补 reference-definition 分支，refstyle 定义 `[id]: FOO.md` 入扫描面，补 refstyle 负向 fixture（构造「refstyle 引用白名单外 `.md` → exit 2」）；N8 —— pin-17 词锚限定在**表格行**内匹配（如 `^\|\s*.*<host>.*\|` 表行形态），或对该 host 断言「词锚 ∧ 表行」双命中，补「删适配表行但保留 tagline 枚举句 → exit 2」负向 fixture（即 V1 决定性构造的固化）；N9 —— pin-08 提取锁定**语义格位**（状态列/约定列），排除同行路径、链接、文件名、slug 中的版本形态串，`X_Y` / `X_Y_Z` 前缀式一律不计入版本串，补「改坏状态格版本串 → exit 2」回归锁。
- **非范围**：不重构 pins 引擎架构；不改既有钉面的判定语义（仅提取口径三处定点）；不动 S2。
- **验收要点**：三个负向 fixture 修复前真红、修复后转绿（即 V1 的三组构造机械化复现）；`pins check` 全量 PASS 且对现行 `README.md` / `docs/spec/README.md` 零误伤（以现行合规文件做回归）；pin-08 严化后「状态格写什么版本号必须影响结果」（对照 §3.J lead 复现实验反转）。
- **风险**：N9 语义格位锁定依赖 spec 索引表列序约定 → 列位口径入 release-pins.yaml 数据（既有先例），表结构变更时钉面同步评审；N8 表行形态正则对 README 双语表格式的脆性 → 以「表行 ∧ 词锚双命中」而非单一复杂正则为优先方案。

## W3 · 输出层统一相对化

- **范围**：N12 —— 相对化收敛为**输出层统一出口**（所有 CLI 输出经统一 toRel 处理，替代逐字段打补丁）；覆盖 V2 实测泄漏清单全部四行（`task lint --json#file` · `task close --json#dest/done_snapshot.path` · `verify/gate-check --json#task` · `task close` 人类输出）；补「任何 `--json` 输出不得含绝对路径」机械断言（测试套件级 · 含 /tmp 靶场）。
- **非范围**：不改 exit code 语义；不动 `--json` 信封键集（契约「只增不改」· 值相对化属 2.3-W3 已确立的修复方向延续）。
- **验收要点**：V2 清单四处实测转相对；新机械断言对全命令面生效（构造任一命令传绝对路径入参 → `--json` 输出 grep 仓外绝对形态串为空）；`status --json#task_path` 既有相对化不回退。
- **风险**：统一出口改动面宽，可能遗漏不经出口的直接 print → 机械断言即兜底，验收以断言全绿为准。

## W4 · 资产门禁可观测补全

- **范围**：N2 —— `assets verify` 对 `assets/` 内被排除项（`.bak` 等）输出**显式 warning 清单**（排除生成侧维持不打哈希 · verify 侧可见性补齐）；N5 —— `assets manifest rebuild` 增强提示：输出强制警示「此操作将追认当前资产状态为真值」类文案，评审定是否需 `--yes` 之外的显式确认（维护者动作口径）。
- **非范围**：不做签名/密钥体系（仍仅 sha256 清单）；不把排除项升级为 exit 2（warning 级即可 · 报告建议原文口径）；不接外部遥测。
- **验收要点**：构造「assets/ 内放 `.bak` → verify exit 0 但 warning 点名该文件」；rebuild 输出含追认警示文案（快照断言）；既有 mismatch/missing/extra 三负向 exit 2 不回退。
- **风险**：warning 与 failClosed 输出混在一起可能干扰 CI 判读 → warning 走独立字段/前缀，exit code 语义不变。

## W5 · 物料与对外口径对齐
